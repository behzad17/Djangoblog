# ES-000 — Editorial Studio Product Blueprint

**Status:** Accepted (product design only)  
**Phase:** Product  
**Depends on:** RFC-001 … RFC-007 foundations; production workflow (M1.1–M1.3)  
**Implemented today:** ES-001 News Import (first tool; code under `content_ai/editorial_studio/`)  
**Out of scope for this document:** implementation, database changes, UI coding

---

## 1. Vision

Editorial Studio is the central AI workspace for Peyvand editors.

Editors should never interact directly with PromptBuilder, Workflow, Providers, or AI settings.

Instead they work with simple editorial tools.

Every tool internally uses the same production AI workflow.

Editorial Studio should feel like:

> The AI-powered newsroom of Peyvand.

---

## 2. Product principles

1. **Editors think in tasks — not prompts.**  
   Tools ask for URLs, topics, and articles. Prompt assembly stays inside the engine.

2. **Every tool solves one editorial problem.**  
   No mega-forms. One purpose per tool.

3. **Every tool uses the same workflow.**  
   No bypass of `WorkflowOrchestrator` / PromptBuilder / provider path.

4. **Generated content is always editable.**  
   AI never publishes automatically. Humans approve in Blog Admin.

5. **Metadata remains available.**  
   Editors can inspect workflow, provider, duration, stages, and (later) tokens and evaluation.

## 4. Shared workflow

Every tool uses the production path:

```
Editor
  ↓
WorkflowOrchestrator.execute()
  ↓
Research
  ↓
Source Intelligence
  ↓
Knowledge
  ↓
PromptBuilder
  ↓
Provider
  ↓
Evaluation
  ↓
Draft
```

No tool bypasses the workflow.

---

## 5. Shared output model

Every tool returns the same conceptual result object:

| Field | Required | Notes |
|-------|----------|-------|
| `title` | yes | Working title |
| `body` | yes | Main draft / output text |
| `summary` | yes | May be empty string initially |
| `metadata` | yes | Additive bag for tool-specific fields |
| `workflow_stages` | yes | Stages executed |
| `provider` | yes | Active provider name |
| `duration` | yes | Generation duration (ms) |
| `generated_at` | yes | Timestamp |

**Future fields (do not block V1):**

- confidence  
- cost  
- token usage  
- evaluation score

## 9. Relationship to existing surfaces

| Surface | Role after Editorial Studio |
|---------|-----------------------------|
| **Editorial Studio** | Single product home for all editor-facing AI tools |
| **AI Editorial Workspace (APF-001)** | Legacy compose UI; migrate capabilities into Studio over time |
| **AI Studio (APF-002)** | Admin experiment / evaluation lab — **not** the editor newsroom |
| **Content AI sandbox** | Developer-only; remains non-product |

New editorial AI features ship as Studio tools (ES-xxx), not as new top-level admin apps.

---

## 10. Non-goals

- Auto-publish or silent Blog writes  
- Editor-facing prompt / provider / model configuration  
- Parallel generation pipelines outside `WorkflowOrchestrator`  
- Redesign of infrastructure RFCs  

---

## 11. Success criteria

Editorial Studio becomes the **single workspace** for all AI-assisted editorial work inside Peyvand.

Every future editorial AI feature is implemented inside Editorial Studio.

No standalone AI pages are created outside this product.
