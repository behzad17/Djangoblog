# APF-002 — AI Studio

**Status:** Implemented (compose-only; never writes production)  
**Flag:** `ENABLE_AI_STUDIO`  
**Entry:** Admin → **AI** → **AI Studio**, or `/content-ai/studio/`

---

## 1. Objective

Internal control centre for Peyvand administrators and editors to experiment with, evaluate, and improve AI behaviour **before** changes reach production.

Studio integrates with existing AI architecture. It does not duplicate Prompt, Knowledge, Workflow, Evaluation, Provider, Source, Fact Check, or Editorial Workspace logic.

---

## 2. Architecture

```
Admin UI (staff only)
   ↓
```

## 3. Module overview

| Module | Purpose | Backend |
|--------|---------|---------|
| Prompt Lab | Preview/compare prompt assembly; test generation | `PromptBuilder` |
| Knowledge Lab | Browse packs; compare metadata; injection preview | `parse_knowledge_modules` |
| Provider Lab | Providers, models, capabilities, health placeholders | `list_providers` / `get_provider` |
| Evaluation Lab | Score outputs | `Evaluator` + snapshots |
| Workflow Inspector | Stages, transitions, context | `WorkflowState` / orchestrator |
| Generation History | Session-local records + compare | `StudioSession.history` |
| System Health | Flags, environment, linked features | config + placeholders |
| Future Labs | Reserved (RAG, agents, streaming, …) | UI disabled |

Each module is independently callable via the Studio API.

## 5. Comparison workflow

Studio supports side-by-side comparison without automatic winners:

| Compare | Action |
|---------|--------|
| Prompt A vs B | `prompt_compare` |
| Knowledge pack A vs B | `knowledge_compare` |
| Generation A vs B | `compare_generations` |

Results always include `automatic_winner: null`. Editors decide.

---

## 6. Explainability design

Every Studio action updates `session.last_explanations`.

Test generations store `explainability` with:

- Prompt version / style
- Knowledge version
- Workflow stage
- Source summary
- Evaluation summary
- Environment (`testing` | `experimental`)
- AI reasoning metadata placeholder (`null` until providers expose it)

---

## 7. Evaluation workflow

1. Paste or generate output text
2. Call Evaluation Lab (`evaluate`) or auto-evaluate after `run_test`
3. Inspect overall / metric scores / warnings
4. Optionally compare two history records

Uses RFC-004 exclusively.

## 9. Validation / production safety

Studio **must not**:

- Modify production prompts or knowledge files
- Publish content
- Replace editorial workflow or business logic
- Auto-select comparison winners
- Expose UI to anonymous/public users

Environment modes: `testing` | `experimental` only. `production` is rejected. Session flags: `writes_production=False`, `auto_publish_allowed=False`.
