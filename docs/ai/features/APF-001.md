# APF-001 — AI Editorial Workspace

**Status:** Implemented (compose-only; no auto-publish)  
**Flag:** `ENABLE_AI_EDITORIAL_WORKSPACE`  
**Entry:** Admin → Post change form → **Open Editorial Workspace**, or `/content-ai/workspace/`  
**v2 / Intelligence v1:** Multi-layer classification — Content Type, Editorial Goal, Writing Style — plus content-type prompt registry.

---

## 1. Objective

First end-user AI feature for Peyvand: an **editorial assistant workspace**, not a one-shot article generator.

Editors collaborate with AI across research → classify → draft → review. The editor remains in control. Every AI action is reviewable. Nothing publishes automatically.

The workspace no longer assumes every source is news. After ingest it classifies **content type**, **editorial goal**, and **writing style**, then selects the matching generation template.

---

## 2. Architecture

The workspace **composes** existing RFCs; it does not reimplement them.

| Layer | Package | Role in workspace |
|-------|---------|-------------------|
| RFC-001 Prompt Engine | `content_ai/prompts/` | Via existing generation path when flags allow |
| RFC-002 Knowledge Engine | `content_ai/knowledge/` | Via existing generation path when flags allow |
| RFC-003 Editorial Workflow | `content_ai/workflow/` | Stage display + manual safe transitions |
| RFC-004 Evaluation | `content_ai/evaluation/` | Evaluation panel |
| RFC-005 Providers | `content_ai/providers/` | Via `EditorialAIService` |
| RFC-006 Source Intelligence | `content_ai/source/` | URL fetch + readable extract on ingest; trust ranking still stubbed |
| RFC-007 Fact Checking | `content_ai/fact_check/` | Fact-check panel (no auto-verify) |
| Content types (v1/v2) | `content_ai/editorial/content_types/` | Registry, classifier, goals, styles, templates |

**Orchestrator:** `content_ai.workspace.services.WorkspaceService`  
**Session:** Django session store (`content_ai.workspace.store`) — local history architecture only  
**UI:** Admin templates + static CSS/JS under `content_ai/static/content_ai/`

```
Admin UI
   ↓
Workspace views / JSON API
   ↓
WorkspaceService
   ├── classify_content / detect_editorial_goal / detect_writing_style
   ├── CONTENT_TYPE_REGISTRY
   ├── EditorialAIService      (content-aware two-pass draft)
   ├── SourceInspector         (RFC-006 stub)
   ├── FactChecker             (RFC-007)
   ├── Evaluator               (RFC-004)
   └── WorkflowState           (RFC-003 labels + safe manual moves)
```

## 3. Editorial Intelligence v1 flow

```
Source ingest
  → metadata extract
  → content type classification (+ confidence / reasons)
  → editorial goal detection (+ confidence)
  → writing style detection (+ confidence)
  → editor override (optional — type / goal / style)
  → content-type template selection
  → generate headline/title
  → generate lead/introduction (dynamic label)
  → generate body
  → summary
  → SEO / fact check / human approval
```

Defaults remain **news + inform + journalistic** when signals are weak (backwards compatible).

## 4. Workspace layout

Modular four-region UI:

| Region | Panel | Purpose |
|--------|-------|---------|
| Top | Pipeline indicator | ✓ Source imported … Ready for publication |
| Left | Source | URL/text, research notes |
| Center | Editorial Intelligence + article | Type / goal / style overrides above generated article |
| Right | AI assistant | Content-type-filtered actions + explainability |
| Bottom | Validation | Fact check, source intelligence, SEO, evaluation |

### Editorial Intelligence panel

Above the generated article:

- Content Type (editable) + confidence %
- Editorial Goal (editable) + confidence %
- Writing Style (editable) + confidence %
- Reasoning summary, prompt template id, prompt version

Changing any field switches the prompt template before generation.

## 5. CONTENT_TYPE_REGISTRY

Configured in `content_ai/editorial/content_types/registry.py`.

Each type defines:

- generation template id (`{type}.v1`)
- headline / lead strategies
- body structure
- default editorial goal
- default writing style
- assistant action ids
- SEO / evaluation strategy keys

Supported types include News, Guide, How-to, Report, Reportage, Interview, Analysis, Opinion, Explainer, FAQ, Press Release, Announcement, Event, Review, Feature, Editorial, Community Story, Other.

Add new types by registering a `ContentTypeProfile` — avoid scattered if/else.

## 6. Panels overview

### Source

- Paste URL / plain text / notes
- **Ingest Source** fetches the URL, extracts the main article body, and fills Text / notes automatically
- Import existing article by Post ID (read-only into session)
- Auto-classify type + goal + style after ingest
- Recommend Blog category from the full imported article (confidence + top 3 + explainability)
- If extraction fails, the editor sees an explicit error and can paste text manually

### Article

- Editorial Intelligence panel for overrides
- Generate full draft via content-aware `EditorialAIService`
- Lead label updates with content type (Lead / Introduction / Executive summary / Opening context / …)
- Independently editable sections
- **Save draft to Blog** creates or updates a Draft `Post` (never publishes)

### AI assistant

Catalogue in `content_ai/workspace/actions.py`, filtered by registry. Examples:

- News: Improve headline, Rewrite lead, Make neutral, Improve SEO
- Guide: Improve steps, Simplify instructions, Add warnings, Improve structure
- Interview: Improve introduction, Condense answers, Improve flow
- Analysis: Strengthen logic, Neutralise tone, Improve clarity

### Explainability

Shows detected type / goal / style, confidence scores, reasoning, prompt template, and prompt version.

### Pipeline indicator

Tracks: source imported → metadata → type classified → goal → style → draft → SEO → fact check → ready for publication.


### Fact check

Uses `FactChecker.check_text`. No automatic verification / adjudication.

### Source intelligence

Uses `SourceInspector` stub. No external retrieval.

### SEO

Placeholder fields only (title, meta, slug, keywords, OG, image prompt, schema).

### Evaluation

Uses RFC-004 `Evaluator` + snapshots. Shows scores / overall / warnings.

## 10. Human control & production safety

This feature **must not**:

- Replace existing article creation / Admin AI modal
- Modify publishing logic
- Publish automatically
- Duplicate Prompt / Knowledge / Workflow / Fact / Source engines

Every generated result is editable. Every suggestion is optional.
